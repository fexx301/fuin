# How Fūin is put together

A map for someone opening the code for the first time: what each part does, what it trusts, and where to change things.

## The pieces

| Path | Language | What it is |
|---|---|---|
| `src/fuin/` | Python | The `fuin` command: the owner's workflow and the verifier |
| `contract/` | Rust (NEAR) | The registry contract `registry.fuin.testnet`: seals rounds, numbers and stores each run's commitment, closes rounds. Locked (no access keys). |
| `tee/` | Rust (wasm32-wasip2) | The TEE scorer, run on OutLayer: re-scores a run (`score`), grounds answer keys (`ground`), checks an asked run against its seal (`asked-check`). Pinned by sha256 in `policy/tee-v2.json`. |
| `ask/` | Rust (wasm32-wasip2) | The asker, run as a locked OutLayer project (`ask.fuin.testnet/asker` for round 7, `ask2.fuin.testnet/asker` for new rounds): asks each sealed question once and scores it inside the enclave. Shares `tee/`'s library. |
| `site/` | HTML/JS | The page, including a browser port of the verifier (`verify.js`) that must agree with the Python one. `data.js` is generated by `scripts/build_page.py`. |
| `policy/` | JSON | What the verifier accepts: attestation policies (`attestation-v*.json`), scorer and asker pins (`tee-v2.json`), sigstore's pinned trust root. |
| `examples/` | JSON | The published certificates, and `tampered/`: one-change fixtures, each with its expected verdict. |
| `evidence/` | Markdown, JSON | What each round and fix actually did: transactions, verification output, findings. |
| `scripts/` | Python, shell | Review (`review.sh`), fixtures, page build, leak guard, round helpers. |

## The Python modules

| Module | Role |
|---|---|
| `core.py` | The protocol core: canonical JSON, Merkle commitments, audit size and the block-seeded sample. No network. |
| `policy.py` | The sealed policy (request template, scorer, audit mode) and the exact set the verifier supports. |
| `scorer.py`, `scorer_v1.py` | 0/1 scoring. Their sha256 is sealed, so a scorer is never edited, only added. |
| `inference.py` | Builds each sealed request byte for byte, calls NEAR AI Cloud and fetches the `provider_tee` signature. |
| `e2ee.py` | Request template v3: questions and answers encrypted between the owner and the model's attested key. |
| `attestation.py` | Checks a model's attestation report: Intel TDX quote, NVIDIA GPU verdict, report binding, approved measurements. |
| `provenance.py` | Traces the serving container to a public compose file, and checks SLSA build provenance. |
| `near.py` | NEAR RPC reads (with an archival fallback) and owner writes through `near` CLI (keys stay in the OS keychain). |
| `owner.py` | The owner's round: seal, run, commit, close, reveal (certificates). State lives in `private/<round>/`. |
| `tee.py` | Owner side of every OutLayer task (encrypt, host, execute, collect the record) and the verifier's checks of their evidence. |
| `asker.py` | Owner side of an enclave-asked round: preflight, asks, aggregate, asked-check. |
| `verify.py` | The verifier. Checks form first, then everything offline, then the network; an outage defers, never decides. |
| `policyupdate.py` | Drafts the next attestation policy when NEAR redeploys a model. Approves nothing. |
| `tooling.py`, `diagnose.py`, `cli.py` | `fuin check` and `fuin status`, the revealed-miss reading aid, and the command line. `fuin evaluate` runs whatever step `status` names next. |
| `report.py` | `fuin report`: a shareable HTML and JSON report from certificates and their verdicts. Compares only what is comparable; shows no question. |

## What is trusted, and where it's checked

| Claim on a certificate | Rests on | Checked by |
|---|---|---|
| A named model in a TEE signed each answer | Intel TDX, NVIDIA, NEAR's attested reports, the approved measurements in `policy/` | `attestation.py`, `provenance.py` |
| The set and results were committed in this order | NEAR, and the registry's deployed code | `verify.py` (registry record, the owner's signed transactions) |
| The sample was picked by nobody | A future NEAR block hash | `core.py` |
| Every hidden answer was scored correctly | Intel TDX, OutLayer's workers and key service, the pinned scorer build | `tee.py` (`check_local`, `check_remote`) |
| Each question was asked once, after the seal | The above, the locked asker project, OutLayer's storage | `tee.py` (`check_asked_*`) |
| Answer keys come from their cited docs line | The above, GitHub serving near/docs at a pinned commit | `tee.py` (`check_ground_local`) |

Two verifiers implement every check: `src/fuin/verify.py` and `site/verify.js`. `scripts/test_site_verifier.mjs` runs the browser one in Node on every certificate and fixture, and fails CI when they disagree.
